Abstract
Due to the resource-constraint nature and lack of lightweight computing solutions for diagnostic devices in healthcare IoT, provisioning
time-critical responses is still challenging. In this paper, we propose DC-Health, a Dew Computing enabled IoT healthcare solution for offline
and ultra-low latency decisions. The proposed solution connects a large number of healthcare devices and provisions user-specific services
even when Internet connectivity is not available. The computation module is placed at the extreme edge rather than the cloud to reduce the
complexity and to improve the user-specific services. In addition to the other computing facilities provided by the cloud, fog, and edge, our
solution performs with a negligible dependency on the Internet. We develop a prototype of DC-Health, which monitors the heart condition
using the ECG sensors with end-mile services, flexibility in terms of user-control, and mobility feature. The experimental implementations
show that the proposed architecture minimizes the network response time by at least 92% and 98%, compared to the fog and cloud-based
approaches, respectively. Along with this, the proposed technique also reduces the CPU and memory usages, and response time by around
30% compared to the conventional method.

1. Introduction
To provide smart and ultra-low latency decisions in healthcare IoT applications, the current state-of-the-art solutions
are not sufficient [1]. The key challenges that the current
healthcare infrastructure faces are resource-constraint devices,
lack of lightweight analytical modules, and absence of an
intelligent network. The existing edge-based solutions are not
sufficient as they consume high latency [2]. Concerning these,
new computing architecture is essential, which provides flexibility in terms of user control, mobility, ultra-low latency
decisions, and patient-specific requirements.
Dew computing brings the core concept of cloud computing
in the end devices (e.g., Mobile phones, personal computers)
and solves major problems related to cloud computing technology, such as reliance on internet access. We can install a
Dew framework in a small, lightweight Raspberry-pi device,
but the same thing is not possible for Cloud and Fog computing frameworks. The features like ultra-low latency, zero

2. Related work
Efforts have been made for improved healthcare services
through cloud and edge computing architecture. Existing stateof-the-art are divided into cloud, edge, and dew-based solutions.
There are solutions for task processing in fog/edge network
architectures. Among them, fog selection (e.g., [8,9], and [10])
and task allocation (e.g., [8,11,12] and [13]) approaches are
mostly available. However, flexibility and intelligent decision
making are still challenging. In [14], some solutions incorporate a fog-based solution for saving energy in the healthcare
network. Otto et al. [15] perform real-time signal processing
on sensor nodes, whereas, Gia et al. [16] utilize a low power
transmission protocol to save transmission energy for sensor
nodes. In [17], Want et al. try to analyze sensor data in realtime on the local edge network to provide support locally to
the users. IoT based smart e-healthcare system has many challenges, such as energy efficiency, reliability, mobility, quick
response, scalability, etc. Rahman et al. [18] try to solve these
issues using Fog-assisted IoT architecture. Similarly, Subhro
et al. [19] try to improve the QoS of the smart e-healthcare
application by introducing mobile edge computing. In [20],
the UbeHealth framework uses edge computing, deep learning,
and IoT to address the various smart health challenges. The
framework empowers an improved network quality of service.
Deep learning was used to predict network traffic to optimize
data rates, data caching, and routing decisions.

3. DC-health: The proposed architecture
To deploy a smart dew computing-based e-healthcare system with all the healthcare industry’s specific services, it is
necessary to perform all execution in a localized way instead
of the cloud. The proposed architecture aims to provide a usercentric, flexible, personalized, and instantaneous response to
given jobs. With this architecture, we can easily minimize the
dependency on the Internet. In this experiment, the proposed
architecture was implemented in a mobile smart phone device.
Mobile devices have a tremendous potential to contribute to
Dew architecture due to its ability to provide services for
many hours without being plugged into the electricity, and
the proximity characteristics of the smartphone to the enduser. Mobile smartphone-based dew device makes it more
suitable to provide the services even the user is moving from
one place to another. The proposed dew computing-based
architecture acts as a personalized health assistant to a user
without depending upon the existing computing model. As
shown in Fig. 1, each dew-device is a lightweight device that
operates on the dew framework particular module like cloud
synchronization, dew-specific database, dew server lightweight
analysis, and GUI. All these modules are intended to provide
full facilities to the user.
In this paper, to develop the DC-Health architecture in a
mobile smart phone we have installed the python environment using the Pydroid-3 mobile application and executed the
MQTT protocol. The smartphone was acting as an MQTT
client and communicated with the MQTT publisher via the
MQTT broker. The experimented ECG dataset was stored in
the MQTT publisher and just like the sensor device it sends
the data continuously to the MQTT client in a regular interval
of time. After receiving each signal, the MQTT client executed
the proposed trained CNN module and declared the result,
and stored it in the local MySQL server. The proposed dew
based e-health architecture has experimented in an ECG based
healthcare monitoring system, where both normal and abnormal heart conditions are monitored. As shown in Fig. 1, each
dew device collects the real-time streaming health information
of different users and performs the required analysis, and
update the user with the current health condition. As drawn
in the flowchart given in Fig. 2, each dew device collects BS
information from the connected patients and performs some
analysis. The analysis module examines the healthcare data

4.1. Experimental setup
To perform this Dew-health experiment, we have set up
our dew framework in a smartphone environment. Initially,
we developed the lightweight CNN model to support the Dew
device. To integrate the proposed CNN model in the Dew
device, at first, we have installed the python environment and
the python packages required to execute the developed CNN
model. Finally, the CNN model was linked with the MQTT
protocol and MYSQL server to receive input ECG signal and
to store the output result. Here, we have implemented an ECG
based health monitoring system. We have used iFogSim [23],
to simulate the proposed Dew health architecture. The configuration of the cloud, Fog, and Dew devices considered in the
simulation are given in Table 1. For the experimental setup,
all the devices are organized in a three-tier hierarchical order
as shown in Fig. 1.
The maximum number of Dew devices considered is 3 and
each of them is connecting to 1 Fog device. In this experiment,
we have set the uplink bandwidth of cloud and fog to remain
the same, which is 100 Mbps. But it is different in dew
computing, which is 50 Mbps. For evaluation of bandwidth
utilization, the average link bandwidth is taken from all the
link from Dew devices to the remote cloud.
To get the correct results, the simulation is carried out ten
times and an average of them are considered in the presented
results. The details of the parameters used in the simulation
study are listed in Table 2. To implement the lightweight
analysis model, we have worked with an ECG dataset collected
from the MIT-BIH arrhythmia database of PhysioNet [24].
This dataset consists of 1000 ECG records from 6 different
types of arrhythmia. To assess the effectiveness of the proposed lightweight scheme, it is verified with three existing
basic CNN architectures such as LeNet, VGG16, and VGG19.

5. Conclusion
This paper presented a Dew-based lightweight computing
scheme for IoT to support the flexible healthcare solution.
The proposed solution overcomes the challenges like timecriticality, flexibility, and lightweight services which are essential for healthcare IoT. Further, we proposed a dew-based
computing architecture for user-specific healthcare services.
The developed dew devices efficiently use lightweight modules
to execute a specific task at the extreme edge of the network.
Finally, the proposed solution is tested over a real prototype for
lab-scale analysis. The proposed solution is found to be comparatively efficient in terms of latency, response time, energy
consumption, CPU usage, memory usage, and accuracy.
In the future, we plan to improve DC-Health for more
complex healthcare scenarios with heterogeneous devices. In
addition to this, we plan to test the proposed scheme over a
large-scale IoT testbed.
